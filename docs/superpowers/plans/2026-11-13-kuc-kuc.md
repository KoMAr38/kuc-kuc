# Kuc-kuc Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When dangerous weather is forecast, phone an older person who lives alone, interpret their spoken answer, send a neighbour to knock if needed, and show the family everything — plus a public demo a hackathon judge can try on their own phone.

**Architecture:** Three scale-to-zero Cloud Run services (`web`, `engine`, `voice`) and two Cloud Run jobs (`forecast-scan`, `loadtest`) built from one image. They talk only through Pub/Sub (topic `events`), Cloud Tasks (queues `calls`, `calls-sim`, `timers`) and Firestore. All decisions live in one pure state machine in `engine`; `voice` is the only code that touches telephony.

**Tech Stack:** Python 3.12, FastAPI, pydantic v2, pytest; Firestore, Pub/Sub, Cloud Tasks, Cloud Scheduler, Cloud Storage, Secret Manager; Vertex AI Gemini (audio in, JSON out) via `google-genai`; Cloud Text-to-Speech Chirp 3 HD; Twilio Programmable Voice + Verify; Open-Meteo; Telegram Bot API. No Docker locally — images build with Cloud Build.

**Spec:** `docs/2026-11-13-kuc-kuc-dizajn.md` (Serbian). Section numbers below (§) refer to it.

## Global Constraints

- Python 3.12, FastAPI, one repository, one container image. MIT licence. Public site and README in English.
- Region `europe-west1`. Every service runs with `--min-instances 0`.
- Call languages: `sr` and `en` only. Serbian text is sent to speech synthesis in Cyrillic.
- Never rely on keypad tones; answers are spoken.
- Scheduled calls to the person only between 08:00 and 20:00 in the person's timezone. An escalation in progress always finishes, at any hour. "Call now" works at any hour.
- At most 6 calls per person per day (calls to the person only, not neighbours). One kill switch stops all new calls. Whenever a real call is blocked, the family gets an urgent Telegram message.
- Any doubt is treated as a problem: unclear, silent, wrong-person or failed interpretation never becomes `ok`.
- Recording at most 8 seconds; call at most 60 seconds. Recordings kept 7 days in our bucket and deleted from Twilio right after download. Demo data deleted after 24 hours.
- Store only name, phone, language, gender, approximate location. No street address. Phone numbers never appear in logs, public pages, the repository or test fixtures (use `+15005550006`-style fakes).
- Hazard thresholds (configurable by env): heat = apparent temperature ≥ 35 °C; cold = temperature ≤ −10 °C; wind = gusts ≥ 80 km/h; snow = ≥ 20 cm in 24 h.
- Demo: allowed countries US, CA, GB, NO; 2 runs per number per day; daily dollar cap 15 on 2026-11-20 and 5 on other days; demo off after 2026-12-04; demo off when Twilio balance < 10 USD. Demo limits never block a real person's call.
- Twilio webhooks are rejected unless the signature validates.
- Commit locally after each task. Push to GitHub only when the user says so.

## Review Focus

1. **Pick-up then silence or hang-up.** The person lifts the receiver and says nothing, or hangs up mid-question. Expected: `unclear`, one re-ask if still on the line, then the neighbour. Never `ok`. (Task 6)
2. **The same event or webhook delivered twice.** Pub/Sub and Twilio both retry. Expected: one neighbour call, one notification, one completion. (Tasks 6, 7)
3. **Speech or interpretation service fails during a live call.** Expected: the call still ends with the neutral closing, the answer is `unclear`, Twilio gets valid TwiML, not a 500. (Task 6)
4. **Late discovery and timezone edges.** A hazard found at 12:00 for today, at 19:59, or across a daylight-saving change. Expected: times are computed in the person's timezone; a missed check time runs immediately only inside 08:00–20:00. (Task 14)
5. **Awkward phone input in the demo.** `(415) 555-0100`, a number from a country not on the list, a premium-rate or short number. Expected: normalised to E.164 or refused with a clear message; premium and short numbers are never dialled. (Task 9)

Serbian texts are copied verbatim from §8. Decisions the spec leaves open:

- Hazard phrase after "Danas je" / "danas je": heat `veoma vruće`, cold `veoma hladno`, wind `jak vetar`, snow `mnogo snega`. `CHECK_MANUAL` drops the hazard sentence: `Dobar dan, {ime}. Ovde Kuc-kuc. Zovem da proverim: jeste li dobro?`
- Heads-up middle sentences. heat: `Sutra će biti veoma vruće, do {temp} stepeni. Pijte dosta vode i ne izlazite u podne.` cold: as in §8. wind: `Sutra će duvati jak vetar. Zatvorite prozore i ne izlazite ako ne morate.` snow: `Sutra će pasti mnogo snega. Ne izlazite ako ne morate i imajte hranu i lekove u kući.`
- Numbers: negative values are spoken as `minus 12`; values are rounded to whole numbers.
- Gender: `do nje` / `do njega`; `da joj nije dobro` / `da mu nije dobro`.
- `question_for`: person scripts except intro → `WELLBEING`; both intros and both neighbour asks → `YES_NO`; `NEIGHBOR_FOLLOWUP` → `NEIGHBOR_REPORT`.
- `closing`: person + `OK` → "Hvala, {ime}. Čuvajte se. Doviđenja."; person + `NEEDS_HELP`/`UNCLEAR` on a check/manual/heads-up → "Javiću komšiji da svrati do vas. Doviđenja."; everything else → neutral "Hvala. Doviđenja."
- English copy: `Hello, {name}. This is Kuc-kuc. Today is very hot. I'm calling to check on you: are you okay?` (very hot / very cold / very windy / very snowy). Re-ask: `Sorry, I didn't catch that. Are you okay? Please say yes or no.` Closings: `Thank you, {name}. Take care. Goodbye.` / `I'll ask your neighbour to stop by. Goodbye.` / `Thank you. Goodbye.` Neighbour: `Hello, {neighbor}. This is Kuc-kuc. {name} isn't answering the phone, and today is very hot. Can you go and check on her now? Please say yes or no.` Follow-up: `Hello, {neighbor}. Did you see {name}? Please say: she is fine, or: she needs help.` The remaining English lines translate §8 in the same plain register. English values are passed already in the unit to be spoken (the demo passes Fahrenheit).

**Interfaces — Produces:**

```python
@dataclass(frozen=True) class Due: pass
@dataclass(frozen=True) class CallDone: target: Target; script: ScriptKind; answer: Answer
@dataclass(frozen=True) class CallBlocked: reason: str
Input = Due | CallDone | CallBlocked

@dataclass(frozen=True) class PlaceCall: target: Target; neighbor_index: int | None; script: ScriptKind; delay_s: int = 0
@dataclass(frozen=True) class Notify: key: str; urgent: bool = False
@dataclass(frozen=True) class SetStatus: target: Target; status: PersonStatus
@dataclass(frozen=True) class Close: result: Result
Action = PlaceCall | Notify | SetStatus | Close

PERSON_RETRY_S = 600; PERSON_MAX_ATTEMPTS = 3
HEADSUP_RETRY_S = 1800; HEADSUP_MAX_ATTEMPTS = 2
NEIGHBOR_RETRY_S = 300; NEIGHBOR_MAX_ATTEMPTS = 2
FOLLOWUP_DELAY_S = 1200; FOLLOWUP_RETRY_S = 300; FOLLOWUP_MAX_ATTEMPTS = 2

def step(ep: Episode, ev: Input, neighbor_count: int) -> tuple[Episode, list[Action]]
```

`step` is pure: no clock, no I/O. `neighbor_count` is the number of neighbours with status `ACTIVE` (for `DEMO` and `SIM` the engine passes 1). Rules, all from §5.3–5.5 and §9:

| Episode | Input | Result |
|---|---|---|
| any, state `CLOSED` | anything | no change, no actions |
| any | `CallBlocked` | `Notify("call_blocked", urgent=True)`, `Close(BLOCKED)` |
| `CHECK`/`MANUAL`/`DEMO`/`SIM` | `Due` | `PlaceCall(PERSON, None, CHECK or CHECK_MANUAL)`; `MANUAL` uses `CHECK_MANUAL` |
| same | person `OK` | `Notify("call_ok")`, `Close(OK)` |
| same | person `NEEDS_HELP` | set `unwell`, `Notify("call_unwell", urgent=True)`, start neighbour chain with `NEIGHBOR_ASK_UNWELL` |
| same | person `UNCLEAR` | start neighbour chain with `NEIGHBOR_ASK_SILENT` |
| same | person `NO_ANSWER` | attempt < 3 → `PlaceCall(PERSON, …, delay 600)`; else neighbour chain with `NEIGHBOR_ASK_SILENT` |
| `HEADSUP` | `Due` | `PlaceCall(PERSON, None, HEADSUP)` |
| `HEADSUP` | person `OK` | `Notify("headsup_ok")`, `Close(OK)` |
| `HEADSUP` | person `NEEDS_HELP` | as for a check |
| `HEADSUP` | person `UNCLEAR`/`NO_ANSWER` | attempt < 2 → retry in 1800; else `Notify("headsup_missed")`, `Close(NOT_DELIVERED)` |
| neighbour chain start | — | no active neighbours → `Notify("nobody_reachable", urgent=True)`, `Close(UNREACHABLE)`; else `PlaceCall(NEIGHBOR, i, ask)`, `Notify("neighbor_called")` |
| ask | neighbour `YES` | `Notify("neighbor_going")`, `PlaceCall(NEIGHBOR, i, NEIGHBOR_FOLLOWUP, delay 1200)`, state `WAITING_FOLLOWUP` |
| ask | neighbour `NO`/`UNCLEAR` | next neighbour (or `nobody_reachable` as above) |
| ask | neighbour `NO_ANSWER` | attempt < 2 → retry same neighbour in 300; else next neighbour |
| follow-up | `OK` | `Notify("resolved_ok")`, `Close(OK_BY_NEIGHBOR)` |
| follow-up | `NEEDS_HELP` | `Notify("needs_help_194", urgent=True)`, `Close(NEEDS_HELP)` |
| follow-up | `UNCLEAR`/`NO_ANSWER` | attempt < 2 → retry in 300; else `Notify("neighbor_unconfirmed", urgent=True)`, `Close(UNCONFIRMED)` |
| `INTRO` | `Due` | `PlaceCall(PERSON, None, INTRO_PERSON)` |
| `INTRO` | `YES` | `SetStatus(PERSON, ACTIVE)`, `Notify("consent_yes")`, `Close(CONSENTED)` |
| `INTRO` | `NO` | `SetStatus(PERSON, DECLINED)`, `Notify("consent_no")`, `Close(DECLINED)` |
| `INTRO` | `UNCLEAR`/`NO_ANSWER` | attempt < 3 → retry in 600; else `Notify("consent_missing")`, `Close(NO_CONSENT)` |
| `INTRO_NEIGHBOR` | — | same as `INTRO` with `Target.NEIGHBOR`, script `INTRO_NEIGHBOR`, `neighbor_index` 0 (the episode carries `neighbor_id`) |

The follow-up retry (unanswered follow-up → one more try → urgent) is a decision of this plan; §5.5 is silent on it.

Routes and behaviour:

| Route | Caller | Behaviour |
|---|---|---|
| `POST /calls/start` body `{"call_id"}` | Cloud Tasks | 403 unless `verify_oidc(request)`. Load call; if missing or status not `queued` → 200, do nothing. If `get_runtime().kill_switch` → `patch_call(status="blocked")`, publish `call.blocked` `{call_id, episode_id, reason: "kill_switch"}`, 200. If `provider == "simulated"` → `complete_call` with `Answer(params["sim_answer"])`, publish `call.completed`, 200. Otherwise synthesise opening, re-ask and all three closings (so the live call never waits for synthesis); on synthesis failure publish `call.blocked` reason `tts_failed`. Then `place_call`, `patch_call(status="placed", provider_sid=…)`, timeline `call_placed` `{role}`. |
| `POST /twiml/{call_id}` | Twilio on answer | Timeline `call_answered`. TwiML: `<Play>{voice_public_url}/audio/{key}</Play>`, `<Record action="…/recording/{call_id}?n=1" maxLength="8" timeout="3" playBeep="false" trim="trim-silence"/>`, `<Redirect method="POST">…/recording/{call_id}?n=1&amp;empty=1</Redirect>`. |
| `POST /recording/{call_id}?n=&empty=` | Twilio | If the call is already `completed` → neutral closing + `<Hangup/>`. If `empty=1` → answer `UNCLEAR` without fetching. Else fetch WAV, store at `recordings/{call_id}-{n}.wav`, delete at provider, interpret. Any exception → `UNCLEAR`. If `UNCLEAR` and `n == 1` → `<Play>` re-ask + `<Record … n=2>` + `<Redirect … n=2&empty=1>`. Otherwise `complete_call`, publish `call.completed`, timeline `answer_interpreted` `{role, answer, transcript}`, return `<Play>` closing + `<Hangup/>`. |
| `POST /status/{call_id}` | Twilio | `CallStatus` in `busy`, `no-answer`, `failed`, `canceled` → complete with `NO_ANSWER`. `completed` and the call is not yet completed (hung up early) → complete with `UNCLEAR`. Publish `call.completed` only when `complete_call` returned True. |
| `GET /audio/{name}` | Twilio | Serves `audio/{name}` from blobs as `audio/mpeg`; 404 otherwise. |

| `intro.requested` `{person_id}` or `{neighbor_id}` | `start_episode` kind `INTRO` or `INTRO_NEIGHBOR` |
| `alert.created` `{alert_id}` | Task 14 adds this; until then ignore |
| `call.completed` | load call and episode; `update_episode` runs `step(ep, CallDone(...), n)`; skip if `event_id` in `seen_event_ids` (keep the last 20) |
| `call.blocked` | same with `CallBlocked(reason)` |
| `POST /timers` | `update_episode` with `Due`; ignore if state is not `SCHEDULED` |

Executing actions, in order, after the transaction commits:

- `PlaceCall`: resolve the callee (person, or the `neighbor_index`-th `ACTIVE` neighbour; for `INTRO_NEIGHBOR` the episode's `neighbor_id`; for `DEMO` and `SIM` the neighbour is the person's own phone and name "neighbour"). Build `CallRecord` with `params_to_dict(ScriptParams(...))`, `provider="simulated"` when `person.sim`. If `call_block_reason` is set: timeline `call_blocked`, publish `call.blocked`. Else `put_call`, `enqueue_call(call.id, delay_s, sim=person.sim)`, timeline `call_queued` `{role, delay_s}`.
- `Notify`: `notifier.send(person.owner_uid, key, params, urgent)`, timeline `family_notified` `{key, urgent}`. Params: `name`, `neighbor`, `hazard`.
- `SetStatus`: update the person or neighbour.
- `Close`: timeline `episode_closed` `{result}`.

For `SIM` episodes, each simulated call takes its `sim_answer` from the episode's `sim_answers` list in order.

Message copy (Serbian, exact): `needs_help_194` → `HITNO: {neighbor} javlja da {name} treba pomoć. Pozovi hitnu pomoć 194.` `nobody_reachable` → `HITNO: {name} se ne javlja i nijedan komšija nije dostupan. **Interfaces — Consumes:** `hazards_for`, `fetch_forecast`, `cell_of`, `Store.create_alert`, `alert_exists`, `create_episode`, `TaskQueue.enqueue_due`. **Produces:**

```python
def plan_calls(alert: Alert, tz: str, now: datetime, previous_day_alert: bool) -> list[tuple[EpisodeKind, datetime]]   # UTC datetimes
def run_scan(deps: Deps, http_get: Callable[[str, dict], dict]) -> int      # number of alerts created
```

`plan_calls`: heads-up at 17:00 local on `alert.day − 1`, only if `previous_day_alert` is False and that moment is after `now`. Check at 17:00 local on `alert.day` for heat, 10:00 for the others; if that moment has passed and `now` is on `alert.day` between 08:00 and 20:00 local → check at `now`; otherwise no check. `run_scan`: active persons only (not paused, not demo, not sim), one fetch per cell, alerts for today and tomorrow in the person's timezone, `create_alert` then publish `alert.created` only when it returned True. A fetch failure for one cell is logged and the scan continues. Engine on `alert.created`: send the `alert_created` notification; `previous_day_alert = alert_exists(f"{person_id}:{hazard}:{day − 1}")`; for each planned call `create_episode` with id `f"{person_id}:{day}:{kind}"`; only when it returned True, `enqueue_due`. Engine on `/timers` for a `HEADSUP` or `CHECK` episode whose person is no longer `ACTIVE` (paused or declined since scheduling): close with `NOT_DELIVERED`, no call, no notification.
